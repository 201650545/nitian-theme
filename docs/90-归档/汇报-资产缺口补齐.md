## 附带修复 · 立绘卡切换会话卡死中间态（2026-08-31）

**症状**：新开洞府后立绘卡仍悬浮挡住界面（用户二次报告，第一次修复无效）。
**根因**：`.empty` 用 CSS `transition: opacity .5s` 动画，轮询里反复写 `style.opacity` 时一条 CSSTransition 会卡死在 progress 0（inline=0 但 computed=1，永不推进）——背景合成层过渡不生效。
**修正**：只在值变化时写入；写前 `style.transition="none"` 收掉动画；隐藏时叠加 `visibility:hidden` 兜底。
验证：新会话 `{"inline":"0","computed":"0","vis":"hidden"}`，立绘卡消失。

## 附带修复 · 发消息 PI_AI_ERROR JSON 解析失败（2026-08-31）

**症状**：DSH 发消息报 `Unexpected non-whitespace character after JSON at position 210`（PI_AI_ERROR），本轮运行失败。
**根因**：小红书/dots3 渠道（fast 组）流式响应里部分 SSE 事件只隔单个 `\n`；网关透传层 `_SseReasoningStripper.feed()` 用 `\n` join 重组行后原样保留该边界；pi-ai 按 `\n\n` 切分 → 两条 data: 行被拼成一个消息 → JSON.parse 失败（210 = 第一条合法 JSON 的长度）。
**修正**：`api_gateway.py` 的 `_SseReasoningStripper.feed()` 改为对每条完整 `data:` 行强制以 `\n\n` 收尾（事件重定界），空行不透传；重启网关后实测 34 事件全部双换行分隔、无相邻 data 行。
**验证**：DSH 新会话真实发消息 → 正常回复（fast 组 Dots3→Groq 双保险 2 步完成），PI_AI_ERROR 不再出现；页面残留两条错误均为修复前（20:25/20:47）的历史记录。

## 附带修复 · 道藏设置面板显示错乱（2026-09-01）

**症状**：点侧栏底部「道藏」按钮，设置面板被压成 280px 窄条，全部文字一字一行竖排（右侧内容列只剩 40~50px 宽），整个面板错乱不可用。
**根因（两层叠加，都是主题 PAGE_CSS 引入）**：
1. **backdrop-filter 劫持 fixed 包含块**：主题给 `div[class*="_sidebarCol"]` 加了 `backdrop-filter:blur(18px)`。按 CSS 规范，带 backdrop-filter 的元素成为所有 fixed 后代的包含块。设置面板 overlay 是 `position:fixed`（不挂 portal、直接渲染在侧栏 footer 的 settingsArea 里），本应铺满 1600px 视口，被锁死在 280px 侧栏内 → 800px 面板压成 279px。
2. **stacking context 封顶（试错过程）**：第一版把 blur 移到 `::before` 伪元素（伪元素无后代，不再劫持 fixed——这一步正确），但给侧栏加 `isolation:isolate` 建 stacking context 后，面板 z:1000 被封顶在侧栏原子组里，反而被 centerCol 对话区盖住（isolate 子树画在流内层）；改 `z-index:1` 又盖不过 composerSeat(z:7)/状态条(z:2)。
**终稿**：侧栏/详情栏 **只保留 `position:relative`、不带任何 z-index 或 stacking context**；blur 由 `::before(z:-1)` 承担（画在上层 stacking context 的负层，糊住 bglayer 背景不影响内容）。面板 z:1000 直接升出侧栏子树参与全局竞争 → 天然压住一切内容（等同 DSH 原生行为），遮罩正确盖住 composerSeat(z:7)/状态条(z:2)/头部。
**附带**：模态对话框打开时主题 HUD（fixed z 2147400000 永远置顶，会叠在面板上沿）自动隐藏，关闭后恢复——复用 empty-state 轮询的「只在值变化时写入」防 transition 卡中间态模式。
**验证**：面板 800×727 居中；7 个采样点全部命中面板内部（含 composer 区/头部/左下角）；HUD 打开时 opacity 0 / 关闭后恢复 1；关闭面板后对话页完整渲染无残留。侧栏毛玻璃视觉保留。
**弹层回归（同劫持受害者排查）**：修复前侧栏 backdrop-filter 同样劫持了所有挂载在侧栏子树里的 fixed 弹层。修复后三类弹层全部实测正常：① 道藏设置面板（800×727 居中）；② composer 模型选择菜单（423×50 @ 正常位置）；③ 会话操作右键菜单（fixed 218×130，正确跨出侧栏边界）。
**教训（CSS 布局三陷阱）**：① 给会承载 fixed 弹层的容器加 `backdrop-filter/transform/filter/contain/will-change` 会劫持其包含块；② 给该容器加 `isolation:isolate` 或任何 z-index 会把内部弹层封顶在自己层级里，正确做法是容器**不加 stacking context**，让内部 fixed+z 直接参与全局竞争；③ 立绘卡/HUD 这类 always-on-top 主题层遇到模态框要让位（复用防卡死轮询写法）。
