## 1. 产品定义与边界

**一句话**：仙逆修仙养成 × Coding 行为流的轻量陪伴式体验——每次编程会话是王林的一段人生，Token 累计是灵力修为，境界节点是人生里程碑；编程的顺逆映射修道的顺逆。

**不做什么（边界）**：
- 不做通用增强沙盒；不做真实对战/竞技/外扩散营销。
- 素材版权红线：完全个人自用、不商用不发布；唯一红线=不发布、不传播、不入公开仓库（D-20260815-01）。
- 通道层只做 DSH 伴生（首版），不做多端分发。

**解耦预留（伴生→独立）**，每一处都是显式接口，未来切独立 Web 游戏时不改领域只换实现：

| 维度 | 伴生实现 | 独立未来 | 解耦位 |
|---|---|---|---|
| 事件源 | DSH DOM observer + server hook | 原生 IDE/脚本进项目内事件 | **Event Adapter**（A/B） |
| 渲染 | 挂 DSH 页面 DOM / 浮层 | 独立 Canvas 页 | **Renderer 可插拔** |
| 叙事 | JavaScript + 演出脚本 | 同 | **Canon/Journey 独立于运行时** |
| 状态 | localStorage + server | 服务端存档 | **三类状态分离**（§9） |

## 2. 玩家体验目标

1. **陪伴**：王林常驻一角，随用户一起长大；用户即王林，不把游戏当「状态栏挂件」。
2. **仪式感**：破境=全屏电影式演出（旧境碎裂→金光冲屏→新境浮现→印章→判词），不是数字跳变。
3. **挫折可逆为剧情**：报错/重试=遇敌受挫（浮现对应强敌+经典台词），把编程低谷变成剧情高潮前奏。
4. **沉浸文案**：全 UI 仙逆化（洞府/论道/道藏/传讯玉简），不破坏编程可用性，只换叙事语义。

## 3. 核心循环（冻结）

```
Coding 行为 → Event Adapter 标准化 → 积累 Token(修为) → 推进 realmId 与进度窗
  → Journey 依据进度显影(环境/判词/回响)
  → 到阈值 → 破境演出 + 新阶段解锁 → 回到 Coding
```

**冻结理由**：这是系统的心脏，改变它必须升版。唯一允许的演进是「响应层加内容」，不是「改反应方式」。

---

## 4. 成长与境界模型

- **主干**：6 大境界（炼气→筑基→结丹→元婴→化神→问鼎），常驻状态栏。
- **细分**：27 节点 `realmId`（形态矩阵 27/27 已收官），节点=修为里程碑。
- **阈值**：每节点 Token 阈值按**对数节奏**排布，取值来源链 `:3000 网关 /api/nitian/usage` → 30s 轮询 → realmId+pct。阈值可一键重校准（跑两周按真实用量调），但**量级与节奏**（对数）不随便动。
- **不变量**：修为只进不退；同一时刻只有一个 realmId 与一个 pct；pct 由修为与所在 node 阈值推导，不独立存储。

## 5. 内容与叙事模型（四层职责，永不混写 —— v3 铁律）

| 层 | 职责 | 解释「什么」 | 谁写 |
|---|---|---|---|
| **Canon** | 王林故事线发生了什么（编年史/节点） | 事件**存在** | 主 Agent（Gemini 考证初稿→校对） |
| **Journey** | 此刻进度窗该显影什么（24 段 chronicleKey） | 何时**显影** | 主 Agent |
| **Coding Event** | 此刻天气（编程实时事件） | 现在**发生什么** | Event Adapter（A/B） |
| **Player State** | 用户记录经历 | 你**经历过**什么 | 运行时 |

**进度四窗**（按 realmId+pct 触发，见 v3 §4）：入世 0–30% / 因起 30–65% / 劫至 65–90% / 临界 90–100%。演出只在**本 session**，不永久命名（痕迹系统 v3.0，无永久命名）。

## 6. 六大系统玩法职责

> 规则：**每个系统必须有 gameplay/叙事职责**；无职责的内容与资产不铺。资产生产必须能追溯到某一系统的职责。

| 系统 | 职责 | 映射到 Coding |
|---|---|---|
| **王林** | 主视角成长：修为/境界/换装/语录 | Token 与境界 |
| **李慕婉** | 陪伴系：因果/心境/感情回响 | 顺境陪伴、里程碑感情线 |
| **藤化元** | 宿敌系：挫折/瓶颈/逆境事件 | 报错、连续失败 |
| **藤家老祖** | 威慑系：大瓶颈/守关/高危沉浸 | 长工期未知、重大失败边缘 |
| **藤家元婴修士** | 敌役系：各境界标配挑战 | 常规任务阻力、重试 |
| **天逆珠** | 时间回溯/存续系：撤销/回滚意象 | `undo`/`revert`/回滚 |

## 7. 运行时总体架构

```
Coding 行为流
   │
   ▼
Event Adapter ──(A: DOM observer ## fail 自动落 B: server hook)──▶ 标准事件契约
   │                                                       error / tool / thinking / task_complete
   ▼
Quota / 修为累积 (server, 30s 轮询 :3000) ──▶ Game State (realmId+pct, 可推导)
   │
   ▼
Journey (何时显影) → Rules → Renderer (▽ 伴生 DOM / ○ 独立 Canvas)
   │
   └──▶ UI / Video / Audio
```

**责任切分**：
- **server**（DSH 插件）：Token 统计、状态持久、修为累计、演进为服务端存档。
- **browser**（client.js）：事件采集、进度窗判断、演出调度、渲染。

## 8. 状态与存档模型（三类分离）

| 类 | 内容 | 存哪 | 特点 |
|---|---|---|---|
| **可推导** | 修为/境界/pct | 不存，Token 累计即得 | 永不漂移 |
| **用户持久** | 外观、仙玉、履历 | localStorage + server | 跨会话 |
| **Session 临时** | 一次性演出、卷轴显影 | 仅本 session | 不命名、不持久（痕迹系统 v3） |

**不变量**：临时态绝不进持久态；持久态不依赖 session 流过什么、只依赖可推导态。

## 9. 资产运行时契约

**URI 维度**：`realmId × style(动漫/真人) × role(王林/敌人/…/特效) × state(五态) × journeyWindow × assetType → URI`

**真源** = 引擎侧 `asset-manifest.schema.json`（已证实 schema 内路径 `realms/<id>/bg.webp|wanglin.png|hero.webp` 与实际产出吻合）。
- **三件套基座**：每境界 `bg.webp`(16:9) / `hero.webp`(3:4 海报) / **角色立绘**（原 `character.png`，运行时按引擎真源为 `wanglin.png`，含 alpha 透明底）。
- **演出片**：破境/遇敌/施法转场、氛围背景（bgm/sfx/transition 当前 null，音频另派）。
- **风格**：动漫/真人 双风格为并行资产，同 realmId 不同 style 各自成组，manifest 选型决定用哪个。

**给无 gameplay 职责的资产下闸**：27/27 收紧，不再加库存；生产只追 §6 职责与纵切焦点。

## 10. 加载性能降级

降级阶梯，任何一级失败自动回落前一级，**绝不允许白屏或者破坏 DSH 主流程**：
1. 完整演出（音/视/动效全开）→
2. 静态海报 + 状态栏 → 
3. 纯 CSS 保底挂件（境界章 + 灵力条文本）→
4. 保底完全不渲染，DSH 原样。

按 journeyWindow 按需取流（入世段不预拉劫至段重演出），降低带宽与内存。

## 11. 事件源兼容策略

- **A-first**：DOM observer 采集（低侵入、实时）。
- **B 补位**：`report_ad-hoc` server hook 补 A 采不到的事件（如长无输出、上下文将满）。
- 共用一个**标准事件契约**（error/tool/thinking/task_complete，见 v3），A/B 只是两个实现。A 退化自动落 B。
- 事件源整体可换（解耦位），换时只动 Event Adapter，不动后续任何层。

## 12. MVP Vertical Slice（化神→婴变纵切 · 婴变期为主导）

**原则**：一个境界做**纵切到底**（修为推进→进度窗→破境演出→新段解锁→回到 Coding），胜过横向铺 27 境都半吊子。

**A1 纵切范围**：节点 `05_huashen → 06_yingbian`（婴变期为主导），全链路：Token 推进 → 四进度窗显影 → 婴变破境全屏演出 → 解锁 → 对 DSH 零侵入。

**粗颗粒检验**：纵切交付后，任何新资产/新系统都按「它让化神→婴变这条纵线更沉浸」做取舍，不再按「凑齐 27 境」。

## 13. 验收指标

| 类 | 指标 |
|---|---|
| **功能** | 修为累计正确、只进不退；pct 与阈值一致；演出在阈值准确触发；session 演出不污染持久态 |
| **体验** | 破境仪式感（是否全屏电影感）；挫折→剧情的映射是否自然；陪伴（王林相位是否随长大）；对 DSH 编程可用性零干扰 |
| **工程** | 事件采集完整率 ≥99%；Event A 退化自动落 B；四级降级任一级可用；伴生→独立切换不需要改领域 |

**唯一验收人口径**：郭老师只看「前端能用 / 转发可调通 / 演出看得见」，技术细节我自定（见记忆）。
