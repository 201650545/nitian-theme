## 一、主链（我的一切工作挂在这条链上）

```
年度产品命题/不变量
   ↓
季度最大未知数（3–6月）
   ↓
A0→A4 Gate（是否有资格继续）
   ↓
月度关键问题（本月更确定什么）
   ↓
本周一个交付闭环
   ↓
今日下一动作
   ↓
运行 / Event Log / 观察 → Evidence → Decision → 重新规划
```

**P0 判断**：一个任务挂不上这条链（帮不了当前 Gate / 不是修复阻断 / 不降低维护风险）→ 进 Parking Lot，不直接开工。

## 三、年度 / 战略（1 年+）

**年度产品命题**：验证「真实 Coding 行为流」能否成为修仙养成的自然输入——而不是一个套皮生产力工具。

**产品不变量（不可破坏）**：
- 修仙养成 × Coding 行为流
- 双轴解耦（realmId × chronicleKey）
- 核心循环（行为映射，非纯任务打卡）
- 单人 / 本地 / 自托管
- 可长期运转

**今年不追求**：巨量剧情 / 全境界奢华 / MMO 内容 / 高复杂战斗 / 大型社交 / 企业级数据系统。

**收缩/重思条件**：若 A1/A2 多轮原型后，Coding→修仙反馈仍只能靠大量内容包装才成立 → 暂停扩展世界观，重审核心命题（防沉没成本）。

## 四、当前季度 / 验证（3–6 月，最重要层）

**主验证命题**：元婴→化神纵切 MVP 能否证明 Coding 行为与修仙成长之间存在足够自然、明确、值得重复的反馈关系？

**三路验证**：
- 体验：有没有"一边 Coding 一边真在修仙"的感觉？
- 结构：双轴解耦在实际运行中是否仍成立？
- 工程：EventAdapter A/B + 三类状态能否支撑核心循环而无大量特殊代码？

季度按**假设**规划，不按功能。功能只是验证材料。

## 五、Gate 体系（产品成熟度轴 = 是否有资格继续）

**不是第五套管理体系**，是"年/季/月/周/日"推进轴上、进下一成熟度阶段的检查点。所有 Gate 同一格式（Gate Card）：

**Gate Card — A1 · 最小可体验核心循环**
- 要证明：Coding行为 → 游戏响应 → 修仙成长 → 再次行动，闭环本身成不成立
- 最小产物：一个不依赖完整剧情/美术/复杂境界即可反复运行的纵切原型
- 通过证据：□ 连续跑 3 轮核心循环 □ 每轮状态变化可理解 □ Coding行为与修仙反馈因果明确 □ 不需要口头解释才能操作 □ 无明显结构性技术阻断
- 明确不解决：完整叙事 / 最终平衡 / 完整美术 / 所有境界 / 长期内容量
- 进入 A2 条件：核心循环"自身成不成立"已无重大疑问，问题开始变成丰富度/稳定性/长期体验/系统化

**每阶段开工前先写 Exit Criteria（≤5 条，满足≥4 条 → Gate Review，而非自动进入）**，防"顺手完善→再补系统→半年后还是 A1"。

## 六、月度 / 周度 / 今日

**本月**：目标不是"完成 70%"，是"到月底对某件事更确定"。本月产物 = **原型 + 证据 + 决策**（1 个可运行原型 + 1 轮真实使用观察 + 1 份问题列表 + 1 个方向决定）。

**本周**：交付一个能运行、体验、观察的**最小闭环**（不是一堆半成品）。本周要有**明确不做清单**。

**今日**：≤1 主任务 + 2 小任务。任务必须能答"今晚我怎么知道做完了"。禁止"完善修仙系统/优化玩法/推进A1"这类非动作。
