## 三、年度 / 战略（1 年+）

**年度产品命题**：验证「真实 Coding 行为流」能否成为修仙养成的自然输入——而不是一个套皮生产力工具。

**产品不变量（不可破坏）**：
- 修仙养成 × Coding 行为流
- 双轴解耦（realmId × chronicleKey）
- 核心循环（行为映射，非纯任务打卡）
- 单人 / 本地 / 自托管
- 可长期运转
- **个人自用·不商用不发布**（素材涉及版权，非商用为唯一红线之外的根本约束，见总设 §1 与 D-20260815-01）— 一切验证、留存、发布决策都基于"只服务我自己的长期使用体验"，不考量拉新/变现/大众留存

**今年不追求**：巨量剧情 / 全境界奢华 / MMO 内容 / 高复杂战斗 / 大型社交 / 企业级数据系统。

**收缩/重思条件**：若 A1/A2 多轮原型后，Coding→修仙反馈仍只能靠大量内容包装才成立 → 暂停扩展世界观，重审核心命题（防沉没成本）。

## 四、当前季度 / 验证（3–6 月，最重要层）

**主验证命题**：化神→婴变纵切 MVP（婴变期为主导）能否证明 Coding 行为与修仙成长之间存在足够自然、明确、**我自己愿意反复使用**的反馈关系？（自用场景，"用户"即我本人——验证的是：我会不会因此更愿持续 Coding，而非大众留存）

**三路验证**：
- 体验：有没有"一边 Coding 一边真在修仙"的感觉？
- 结构：双轴解耦在实际运行中是否仍成立？
- 工程：EventAdapter A/B + 三类状态能否支撑核心循环而无大量特殊代码？

季度按**假设**规划，不按功能。功能只是验证材料。

## 五、Gate 体系（产品成熟度轴 = 是否有资格继续）

**不是第五套管理体系**，是"年/季/月/周/日"推进轴上、进下一成熟度阶段的检查点。所有 Gate 同一格式（Gate Card）：

**Gate Card — A1 · 化神→婴变最小可体验核心循环**（2026-09-03 精改版，GPT 读仓后对齐总设，原文 `C:\Users\Public\nitian_a1_gatecard.txt`）

1. **唯一验证命题**：真实 Coding 行为能否在不干扰 DSH 的前提下，通过「事件级即时反馈 + Token 持续积累成长」形成自然、明确、**我愿意反复使用**的修仙感，并在 `05_huashen → 06_yingbian` 纵切中成立（婴变期为主导）——而非依赖大量剧情/美术包装。
2. **方案 C · 即时反馈 + 长线成长双层**（冻结核心循环上的双层响应，不另造一套循环）：
   - 即时层：Coding Event → EventAdapter 标准事件 → Rules/Renderer → 本 session 可见反馈
   - 长线层：Token 累计 → 推导 realmId+pct → 四进度窗显影 → 阈值破境 → 解锁新阶段 → 回到 Coding
   - **即时事件不得直接改修为/境界；成长唯一依据累计 Token**
3. **A1 最小闭环**：真实 Coding → EventAdapter→标准事件→即时反馈（session 临时） + Token Usage→累计修为→推导 realmId+pct→化神四进度窗→婴变阈值→全屏破境演出→解锁婴变→回到 Coding。范围只对齐已冻结的 A1 Vertical Slice（05→06，婴变期为主导）；资产仅由 Journey/Renderer 按 manifest 取用，不进入成长状态链；存档遵守三类状态（Token 持久；realmId/pct 运行时推导不存；即时演出/显影仅 session）。
4. **Exit Criteria（5条，满足≥4 → Gate Review，非自动进 A2）**：
   - 真实输入成立：真实 Coding 能进标准事件与 Token 链；A/B EventAdapter 共用契约，A 失败可落 B
   - 成长状态正确：Token 只增不退；realmId/pct 与阈值一致可重算、不独立持久化
   - 纵切跑到底：化神四窗→婴变阈值→全屏破境→解锁→回到 Coding 全链可见可验
   - 双层反馈成立：连续 3 次真实 Coding 片段中，即时反馈因果可理解，同时感到长期修为在积累，不靠口头解释
   - 不伤主流程：Session 演出不污染持久态；渲染/事件异常可降级，最坏回到 DSH 原样，对 Coding 零明显干扰
5. **A1 明确不做（6项）**：不改 A0 冻结模型（核心循环/Token=修为只进不退/realmId×chronicleKey/三类状态）；不横铺 27 节点/23 小境界；不实现六系统全量玩法（职责保持冻结）；不重写 v3 Canon/Journey（只消费冻结接口）；不做 A2+ 内容（跨境界二次破境/最终平衡/奢华演出）；不做独立 Web/多端/**飞书桥**（Event Log 只冻结 schema）。
6. **本周唯一主目标**：交付一个可亲手重复验证的化神→婴变纵切骨架——真实/可控 Coding 输入进 EventAdapter+Token 链，看到即时反馈与修为推进，并可用测试阈值完整演示「四窗→婴变破境→解锁→回到 Coding」，同时留下 Event Log 作为 Gate 证据。
7. **今日下一动作**：打通冻结度最高的第一条成长数据流 `(内置API) /api/nitian/usage → cumulativeToken → realm阈值 config → derive realmId+pct → 前端境界/修为显示`。Done=同一 Token 输入稳定推导同一状态；刷新以累计 Token 恢复；代码/存档不独立持久化 pct/realmId。即时 Event 流随后接入，但不得用 Coding Event 直接改修为。

## 六、月度 / 周度 / 今日

**本月**：目标不是"完成 70%"，是"到月底对某件事更确定"。本月产物 = **原型 + 证据 + 决策**（1 个可运行原型 + 1 轮真实使用观察 + 1 份问题列表 + 1 个方向决定）。

**本周**：交付一个能运行、体验、观察的**最小闭环**（不是一堆半成品）。本周要有**明确不做清单**。

**今日**：≤1 主任务 + 2 小任务。任务必须能答"今晚我怎么知道做完了"。禁止"完善修仙系统/优化玩法/推进A1"这类非动作。

## 九、近期工具分工（Obsidian × 飞书 data hub）

> 依据通用规范 `handbook v1.0` → `50-知识管理三工具规范`：Obsidian=分析型文本、GitHub=版本镜像+AI可达、**飞书 data hub=行列结构数据通道**。

**原则：A1 阶段不接飞书桥，只把 Event Log schema 定死 = 预留通道，避免过度工程。**

| 层 | 用谁 | 放什么 |
|---|---|---|
| 分析型文本 | Obsidian（本页） | 规划/决策/设计/Gate Card |
| 代码与文档版本 | GitHub | EventAdapter、存档、schema |
| 行列结构数据（近期=Event Log漏斗） | 飞书 data hub（暂缓启用） | 事件日志→漏斗统计，供跨端/AI读 |

**何时上飞书桥**（二选一触发）：
- 漏斗/Event Log 需要**跨会话/跨设备给 AI 读**（如镜像版GPT分析留存、别台设备观测）；
- 出现第二个消费者（另一进程/工具/脚本）要实时读这份数据。

**A1 现在就做**：把 Event Log 的 schema 定对（日期/事件/上下文/结果/角色状态），将来上桥时它即接线接口。
